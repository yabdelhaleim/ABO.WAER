## 1. `app/Services/CustomerSegmentationService.php` (new)

`namespace App\Services;` — top level because the queue job and the admin controller both consume it (matches `CustomerService`/`CartService` placement, not `Services\Admin/`).

Public typed constants:
```php
public const float VIP_MINIMUM_TOTAL_SPEND = 2000.00;
public const int   VIP_MINIMUM_ORDER_COUNT  = 3;
public const int   CART_ABANDONMENT_HOURS   = 24;
public const int   INACTIVE_DAYS            = 30;
```

**Shared base** — every segment starts here:
```php
Customer::query()
    ->where('is_blocked', false)
    ->whereNotNull('email')
    ->where('email', '<>', '')
```
Blocked customers are excluded everywhere (your decision). The email filter is on the base, not just `All`, because a campaign message needs a deliverable address for every segment.

**Segment queries** — each returns the un-run `Builder`, so `chunkById()` / `count()` can be layered on by the caller:

- `All` → base, untouched.
- `Vip` → base + a grouped `whereHas('orders', …)`:
  ```php
  ->whereHas('orders', fn (Builder $q) => $q
      ->where('status', OrderStatus::Delivered->value)
      ->selectRaw('SUM(total) as total_spend, COUNT(*) as successful_orders')
      ->groupBy('customer_id')
      ->havingRaw('(SUM(total) > ? OR COUNT(*) >= ?)',
          [self::VIP_MINIMUM_TOTAL_SPEND, self::VIP_MINIMUM_ORDER_COUNT]))
  ```
  Single `EXISTS` subquery; a row only exists when the customer has ≥1 delivered order, so the OR cannot leak onto customers with no orders. Eloquent's `select()` is a no-op when columns are already set, so the `selectRaw` survives.
- `CartAbandoners` → base + stale cart line + no completed purchase since:
  ```php
  ->whereHas('cartItems', fn (Builder $q) => $q->where('updated_at', '<=', now()->subHours(self::CART_ABANDONMENT_HOURS)))
  ->whereDoesntHave('orders', fn (Builder $q) => $q->where('created_at', '>', now()->subHours(self::CART_ABANDONMENT_HOURS)))
  ```
  Documented as the standard 24-hour-window approximation (a strict per-line correlation would need a correlated subquery the codebase has no precedent for).
- `Inactive30Days` → base + `created_at <= now()->subDays(30)` + `whereDoesntHave('orders', fn => created_at > now()->subDays(30))`.

**Public API:**
- `getAudienceQuery(CampaignAudience $audience): Builder<Customer>` — lazy, never executes.
- `getAudienceCount(CampaignAudience $audience): int` — `(int) $this->getAudienceQuery($audience)->count()`.

## 3. `app/Jobs/SendCampaignJob.php` (new, creates `app/Jobs/`)

```php
class SendCampaignJob implements ShouldQueue
{
    use Queueable, InteractsWithQueue, SerializesModels;

    public int $tries = 3;
    public int $timeout = 600;
    public array $backoff = [60, 300];
    public int $chunkSize = 100;

    public function __construct(public Campaign $campaign) {}
```

`handle(CustomerSegmentationService $segmentation, CampaignDeliveryService $delivery): void`:
1. `$campaign = $this->campaign->fresh();` — re-read so an `Ended` row short-circuits: `if ($campaign->status === CampaignStatus::Ended) return;`
2. `$campaign->update(['status' => Active, 'sent_at' => now()])`.
3. `$segmentation->getAudienceQuery($campaign->audience)->chunkById($this->chunkSize, function ($customers) …)` — light memory, resumes cleanly on retry.
4. Per chunk: `deliverToCustomer()` for each customer, collect the delivered count, then **one** `increment('sent_count', $delivered)` per chunk (not one UPDATE per customer).
5. After the last chunk: `$campaign->update(['status' => Ended])`.

## 5. `app/Services/Admin/CampaignService.php` (edit)

```php
public function dispatchCampaign(Campaign $campaign): void
{
    DB::transaction(function () use ($campaign): void {
        $locked = Campaign::query()->lockForUpdate()->findOrFail($campaign->id);

        if ($locked->status === CampaignStatus::Ended) {
            throw ValidationException::withMessages(['campaign' => 'Ended campaigns cannot be sent.']);
        }
        if ($locked->status === CampaignStatus::Active) {
            throw ValidationException::withMessages(['campaign' => 'This campaign is already being sent.']);
        }

        $locked->update(['status' => CampaignStatus::Active]);
    });

    // Dispatched after the transaction commits so the worker never reads an uncommitted row.
    SendCampaignJob::dispatch($campaign->fresh());
}
```
Setting `Active` here is what makes the second send-now call fail — it is the "قيد الإرسال" guard, and it also keeps the campaign undeletable while in flight.
